## Technical and conversion audit

- **Rendering:** Vercel rewrites requests to the server-rendered React route handler; published blogs are fetched by slug and unpublished/unknown articles return not-found responses.
- **Canonical/metadata:** The shared metadata module emits canonical URLs on `https://ecomxtra.in`, route-specific metadata, Open Graph/Twitter tags, and Organization, WebSite, Service, BlogPosting, and BreadcrumbList structured data. The source Vercel config intends to redirect `www.ecomxtra.in`, but the live HTTPS `www` hostname did not redirect during the spot check.
- **Crawl/sitemap:** `robots.txt` allows public content, disallows `/admin` and `/api/`, and declares the canonical sitemap. `/sitemap.xml` uses an explicit public-route allowlist and currently published blog rows. Static pages now omit `lastmod` rather than using a misleading fixed date; articles continue to use persisted modification/publication dates.
- **Blog automation:** Gemini JSON output, article field/heading/word-count checks, retry handling, title similarity checks, per-run lease tokens, atomic publish RPC, and server-side image URL verification with curated fallback already exist. The defect was free-form topic selection and lack of an editorial approval gate; a queue and approved-topic prompt were added locally.
- **Images:** Automated posts do not rely solely on an invented model URL: a curated Unsplash fallback is verified by HTTP response and image content type. No paid image service is needed.
- **Leads/analytics:** The contact form validates an inquiry and opens a prefilled WhatsApp draft; the app cannot tell whether the visitor sends it, so it cannot truthfully confirm a generated lead. The repository now includes GTM container `GTM-WGBGWTTN`, Consent Mode defaults (all storage denied), and a first-party accept/reject choice. With explicit analytics consent, page views and the PII-free `contact_form_submit`, `whatsapp_click`, and `phone_click` events are pushed through the data layer. `generate_lead` is not an allowed client event. Configure GA4 Measurement ID `G-DPG068QHD2` inside GTM; see [GTM setup and consent behavior](./google-tag-manager.md). No deployment has occurred, and the published GTM container configuration cannot be verified from this repository.
- **Performance:** The local client build succeeds but reports an 875 KB minified main chunk (above Vite’s 500 KB warning threshold). Public PageSpeed Insights requests returned HTTP 429, so no reliable Lighthouse or CrUX Core Web Vitals result is available; measure before performance claims or code-splitting decisions.

For source rollback, revert only the SEO/blog commits after reviewing their scope; do not discard unrelated working-tree changes.
- **Database:** The new topic-queue migration has not been applied. If it is later applied in staging or production, do not drop the queue or delete editorial rows as a rollback. Prefer a forward, backward-compatible migration that restores the prior RPC behavior while retaining queue data; coordinate code rollback with the deployed schema and verify cron compatibility first.
